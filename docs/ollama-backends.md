# Ollama на Mac и в Docker

`LAB_OLLAMA_BACKEND` выбирает способ запуска модели: `mac` (по умолчанию)
или `docker`. Значение читается при каждом вызове CLI; для последовательности
команд удобно использовать `export` в текущем терминале.

| Режим | Модель | Доступ Hermes |
| --- | --- | --- |
| `mac` | Ollama на macOS, Metal/GPU Apple | Обратный SSH-туннель в VM |
| `docker` | Сервис `ollama` профиля Compose `docker`, CPU Linux VM | Loopback VM |

В обоих случаях Hermes обращается к `http://127.0.0.1:11434/v1` внутри VM.
Бот и Hermes используют существующие контейнеры и приватные настройки.
Модели двух режимов хранятся отдельно: каталог Mac
`~/.local/share/agent-research-lab/ollama/models` и каталог VM
`/srv/agent-lab/ollama`. Домашний каталог Mac в контейнер не монтируется.

## Переключение

Перед сменой backend остановить стенд. Это освобождает занятый порт;
переключение на работающем стенде отклоняется. Диски и модели сохраняются.

```sh
./scripts/lab.sh stop
export LAB_OLLAMA_BACKEND=docker  # Для GPU Mac: mac
./scripts/lab.sh start
./scripts/lab.sh model
./scripts/lab.sh sync
./scripts/lab.sh status
```

`model` скачивает `qwen3.5:4b` и создаёт `agent-lab-qwen:4b` в выбранном
сервере Ollama. Тег поставщика может обновляться: digest установленной
модели нужно сверять через `/api/tags`, если требуется точное сравнение.

`start` в Docker-режиме переносит файлы развёртывания в VM и запускает
только сервис модели; Telegram и Hermes включаются отдельной командой
`./scripts/lab.sh gateway` после настройки. Повторный `start` проверяет
работающий контейнер без его пересоздания. При ошибке останавливаются
ресурсы текущей попытки; уже работающая VM сохраняется.

Docker-профилю нужна VM с 10 GiB памяти. Новый шаблон уже содержит это
значение; существующую VM нужно изменить после остановки:

```sh
./scripts/lab.sh stop
limactl edit agent-research --memory 10 --tty=false
```

Ollama ограничена 2 CPU и 7 GiB памяти, работает под UID/GID 10000,
с read-only rootfs, отдельным томом моделей и loopback API. В образе
закреплены версия 0.35.1 и digest. Облачные функции отключены в обоих режимах.
Остановка `./scripts/lab.sh stop` включает все контейнеры Compose, в том числе
модель Docker, даже если переменная окружения уже сброшена в `mac`.

GPU Apple недоступен Ollama внутри обычного Linux-контейнера на macOS.
Поэтому Docker-профиль этого стенда использует CPU. На Linux с поддерживаемой
GPU требуется отдельная настройка устройств; она в данный профиль не входит.
Источники: [Ollama FAQ](https://docs.ollama.com/faq#how-do-i-use-ollama-with-gpu-acceleration-in-docker),
[официальный Docker-образ](https://docs.ollama.com/docker).

## Методика замера

Исполняемый протокол — [benchmark.py](../infra/ollama/benchmark.py).
Клиент работает внутри Linux VM и обращается к её loopback. Для режима Mac
в путь входит SSH-туннель. Hermes, Telegram и их история в этом замере
не участвуют. Генерации выполняются последовательно, без параллельных тестов.

```sh
limactl shell agent-research -- python3 \
  /srv/agent-lab/deployment/infra/ollama/benchmark.py --backend docker
```

Для Mac сначала переключить стенд и заменить метку на `--backend mac`.
Аргумент benchmark только подписывает результат; backend выбирается через
команды стенда. Перед каждым сравнением сверить версии и digest модели.

Использованы одинаковые Ollama 0.35.1, Qwen3.5 4B Q4_K_M, контекст 65 536,
лимит 128 выходных токенов, `temperature=0`, `seed=42`, `think=false`.
Один запрос выполняется после выгрузки модели через API, затем три — при
загруженной модели. Текст отличается номером прогона, история не передаётся.
Кеш файлов ОС не очищается, поэтому первый запрос не означает холодный диск.

`tokens_per_second` вычисляется как `eval_count / (eval_duration / 10^9)`.
Полное время измерено клиентом; время загрузки и генерации взято из метрик
Ollama. Это запросы без streaming: время первого токена не измеряется.
Описание полей — [Ollama Generate API](https://docs.ollama.com/api/generate).

## Результат 16 октября 2026 года

Время замеров — Лос-Анджелес, PDT (UTC−07:00). Mac: Apple M4, 16 GiB,
питание от сети. В обоих итоговых прогонах VM имеет 2 CPU и 10 GiB;
Docker Ollama ограничена 2 CPU и 7 GiB. Версия 0.35.1, digest модели
`338d8b68d59f40bcfbbeffced53f2f4039bd180f5cd7cd79be5754359b215311` совпали. `/api/ps` подтвердил GPU у Mac и
нулевой `size_vram` у Docker. Каждый запрос получил 62 входных токена
и сгенерировал 128 выходных.

| Показатель | Mac / Metal | Docker / CPU VM |
| --- | --- | --- |
| Первый ответ после выгрузки модели | 11.27 с | 14.20 с |
| Загрузка модели в первом запросе | 6.12 с | 6.57 с |
| Медиана полного времени трёх повторов | 5.29 с | 7.33 с |
| Медиана скорости генерации | 26.02 токена/с | 20.98 токена/с |
| Диапазон скорости повторов | 24.98–27.52 | 15.67–21.51 |

В этой серии Mac генерировал токены в 1.24 раза быстрее;
медиана полного ответа Docker была в 1.38 раза больше.
Для данного Mac основным остаётся режим `mac`; Docker даёт полностью
контейнерный запуск модели с проверенными здесь ресурсами.

Первый Docker-прогон с лимитом 5 GiB завершился HTTP 500 на втором
запросе; cgroup подтвердил один OOM kill. После увеличения лимита до
7 GiB и VM до 10 GiB все четыре запроса прошли. В итоговом cgroup
OOM и OOM kill равны нулю; пик достиг лимита, счётчик `max` равен 2202.
Первоначальный Mac-прогон при VM 8 GiB сохранён отдельно и в таблицу
не включён.

Замер не оценивает длинную историю Hermes, работу инструментов,
доставку Telegram и устойчивость под длительной нагрузкой. Контекст
65 536 настроен, но фактический запрос короткий. Порядок режимов
не рандомизирован, файловый кеш не очищен; на Mac уже использовался swap.
Три повтора показывают текущий разброс, без вывода о средней скорости
для других задач и компьютеров.
