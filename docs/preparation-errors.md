# Ошибки подготовки

Это реальные затруднения при подготовке 10 октября 2026 года.
Исследовательские эксперименты T/P по ним ещё не выполнялись.
Подробные журналы TXT/JSONL, названные ниже, хранятся локально
в `evidence/private/preparation/`. Публикуемые сводные JSON проверок кода
остаются в `evidence/preparation/`.

| Ошибка | Проверка причины | Решение и результат |
| --- | --- | --- |
| При проверке повторного запуска туннель не стал готовым за 30 секунд | SSH-config Lima задаёт `ControlMaster auto`, `ControlPath ssh.sock` и `ControlPersist yes`; туннель наследовал общее соединение и не имел постоянного PID собственного launchd-процесса | Для туннеля отключено SSH-мультиплексирование. Проверка эффективных параметров OpenSSH и реальный повторный запуск прошли; после bootout и отката API в VM недоступен, существующие VM и Ollama сохраняют PID. Результаты в `startup-lifecycle.json` |
| launchd: `Operation not permitted` при чтении скрипта из Documents | В stderr сервиса указан путь скрипта, процесс не стартовал | В plist используется исполняемый файл Ollama напрямую, параметры передаются через EnvironmentVariables; `/api/version` отвечает |
| Docker-тег `0.21.6` не найден | `imagetools inspect` вернул `not found` | Проверен опубликованный `v0.21.6`; сохранён digest multiarch-образа, есть ARM64 |
| `hello-world` не скачался: DNS timeout | `resolvectl status` показал upstream `192.168.5.2`, разрешён был `192.168.5.3` | Исправлены правила DNS и YAML для воспроизведения; повторный `hello-world` прошёл |
| На свежей VM нет `rg` | Диагностическая команда вернула `command not found` | Для проверки эффективного SSH-config использован доступный `sed`; проверка показала запрет пароля и root-входа |
| tar сообщил неизвестные расширенные заголовки macOS | Передавались xattr provenance из локальных файлов | Для передачи указаны `COPYFILE_DISABLE=1` и `--no-xattrs`; повторная синхронизация прошла без предупреждений |
| Hermes не смог скопировать встроенные навыки: `Permission denied` | Родительский `skills/` был создан root при подготовке вложенного каталога | Явно заданы владелец UID/GID 10000 и права родительского каталога; следующий старт добавил 58 встроенных навыков, всего с локальным навыком 59 |
| В standalone Python образа отсутствуют `yaml` и `dotenv` | Проверка запуска шлюза первоначально завершилась ImportError | Проверка использует стандартную библиотеку и `hermes config get --json KEY`, который работает в управляемом runtime Hermes; теперь отклоняет запуск по реальной причине — отсутствующему личному ID |
| В комбинированной проверке модель передала `command` в `web_extract` | В JSONL есть неправильный аргумент и ошибка; вызова терминала или браузера нет | Успешен только поиск. Слова модели о неуспешном curl не считаются доказательством вызова curl; чтение страницы проверяется отдельно |
| `browser_navigate` отсутствовал среди доступных инструментов | В образе есть Chromium, но PM не установил обязательный CLI agent-browser | CLI установлен через `hermes pm install agent-browser`; команда воспроизведения дополнена. Первая неуспешная проверка сохранена в `hermes-browser-before.jsonl` |
| После установки CLI `browser_navigate` всё ещё отсутствовал | Проверены реальные функции Hermes: Chromium найден, но автоматически выбран Browser Use CLI; встроенная проверка браузера возвращала false | Явно заданы `browser.backend: "off"` и `browser.cloud_provider: local`; проверка регистрации теперь возвращает true. В `hermes-browser-check.jsonl` сохранено успешное открытие example.com с заголовком Example Domain |
| При немедленном повторном запуске сервиса launchd: `Bootstrap failed: 5` | Plist прошёл `plutil -lint`; повторный bootstrap того же файла через небольшой промежуток успешно стартовал сервис | Добавлены ограниченные повторные попытки только для кода 5 после `bootout`; остальные ошибки сразу передаются вызывающему |
| Повторный свободный CLI-запрос проверки стенда дал неверные выводы о Docker и GPU | Модель не прочитала `lab-readiness`: запросила публичную документацию, попробовала Docker внутри контейнера без сокета и несуществующий `/api/status` Ollama | CLI и терминал работают, но этот ответ не подтверждает готовность. Реальные `docker ps` в VM и `ollama ps` на Mac показали активный контейнер и 100% GPU. Исходный ответ сохранён в `local-cli-check.jsonl`; инфраструктура по советам модели не изменялась |

Homebrew при установке зависимостей Ollama также переключил системную ссылку
`python3` на 3.14. Ссылка возвращена на ранее установленный Python 3.13.7;
Python 3.14 оставлен как отдельная зависимость. Файлы соседних проектов
не менялись.

Подробные журналы Docker сохранены локально: неуспешный запуск —
`evidence/private/preparation/docker-dns-failure.txt`, повторный успешный —
`evidence/private/preparation/docker-hello-world.txt`.
