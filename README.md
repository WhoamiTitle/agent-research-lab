# Agent Research Lab

Самостоятельный проект для задания №2 об автономных ИИ-агентах как инструменте
исследовательской деятельности веб-инженера.

## Текущий этап

**Локальная подготовка среды по разделу «Ход работы».** Создана отдельная
Ubuntu-VM, установлен Docker и Hermes; локальная модель Ollama работает на GPU
Mac с настроенным контекстом 65 536 токенов. Исследования T1–T5 и эксперименты
P1–P5 ещё не выполнялись. Git инициализирован; основная ветка — `main`.

Telegram ожидает отдельного бота и личного числового ID пользователя.
Шлюз и исследовательские задачи по расписанию не запущены. Полный статус
подготовки и ограничения перечислены в документе ниже.

Проект полностью самостоятельный. Его файлы, инфраструктура и будущий отчёт
создаются отдельно от других учебных проектов.

Все команды `scripts/lab.sh` выполняет типизированный Python CLI.
Обработчики сгруппированы по области в стиле `user_service`; оболочка
передаёт аргументы, а адаптеры управляют Ollama, Lima и Hermes.
Оформление Python, shell и команд разработки следует `fastapi-clean-example`.
Для проверки кода: `uv sync --locked`, затем `make check-ci`.

## Структура

```text
agent-research-lab/
├── README.md
├── .editorconfig
├── .gitignore
├── .pre-commit-config.yaml
├── .github/        # CI для Python 3.13 на macOS
├── pyproject.toml  # Python 3.13+, dev-инструменты и правила проверок
├── uv.lock         # закреплённые dev-зависимости
├── Makefile        # lint, format, test, check-ci, shellcheck и утилиты
├── docs/           # статус, управление стендом, журнал ошибок
├── sources/        # неизменённые тексты задания, происхождение материалов
├── infra/          # VM, Docker/Hermes, Ollama, хранение журналов
├── scripts/        # lab.sh и shell-помощники в makefile/
├── src/agent_lab/  # CLI, прикладные сценарии и инфраструктурные адаптеры
├── tests/          # pytest: unit, integration, tooling, fixtures, mocks
├── licenses/       # MIT-уведомление заимствованного Self-checker
├── templates/      # память, пример .env, диагностический skill
└── evidence/       # проверенные результаты технической подготовки
```

Секреты, история разговоров, модели и диски VM хранятся вне этой папки.

## Следующий шаг

Создать отдельного Telegram-бота, затем локально завершить настройку через
`./scripts/lab.sh setup`. Команды и условия запуска шлюза описаны в
[инструкции](docs/local-setup.md).

Начало исследований выполняется по отдельному указанию.

## Локальный диалог без Telegram

Из корня проекта:

```sh
./scripts/lab.sh chat --cli
```

Выход — `/exit`. Если VM и Ollama остановлены, сначала выполнить
`./scripts/lab.sh start`. CLI использует прежнюю память и инструменты в VM.
Локальный диалог проверен; ошибочный ответ модели о Docker/GPU сохранён
в [журнале ошибок](docs/preparation-errors.md).

Повторный `start` сохраняет работающие VM, Ollama и туннель. При ошибке
запуска освобождаются только компоненты текущей попытки; диски и модели
сохраняются. Поведение проверено на локальном стенде, результаты находятся
в [материалах проверки запуска](evidence/preparation/startup-lifecycle.json).
