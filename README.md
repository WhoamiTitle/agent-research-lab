# Agent Research Lab

Самостоятельный проект для задания №2 об автономных ИИ-агентах как инструменте
исследовательской деятельности веб-инженера.

## Текущий этап

**P1 — развёртывание агента и доказательство автономности.** Создана отдельная
Ubuntu-VM, установлен Docker и Hermes; локальная модель Ollama работает на GPU
Mac с настроенным контекстом 65 536 токенов. Добавлен выбор Ollama на Mac
или в Docker через `LAB_OLLAMA_BACKEND=mac|docker`. Результаты проверок P1 оформлены;
исследования T1–T5 и эксперименты P2–P5 не выполняются.
Git инициализирован; основная ветка — `main`.

Telegram подключён 16 октября 2026 года по времени Лос-Анджелеса;
собственный бот находится в `src/agent_bot` и запускается в VM отдельным
контейнером. Цепочка обработки: Telegram → aiogram → Hermes API → Ollama.
Контрольный диалог через Telegram, Hermes и Ollama подтверждён 16 октября:
получен ответ «Готов.», успешная отправка зафиксирована в журнале бота.
17 октября проверены загрузка диагностического навыка и автоматическое
восстановление Hermes и бота после перезагрузки Linux VM; контрольные
ответы через Ollama отправлены в Telegram. Mac оставался включён.
Также проверена одноразовая cron-задача постоянного шлюза с локальным
результатом при закрытом Telegram-клиенте, по подтверждению пользователя.
Проверка отказа постороннему ещё предстоит.
Итоговая конфигурация, таблицы замеров с условиями, вывод и оставшиеся
требования приведены в [отчёте P1](docs/p1.md).

Проект полностью самостоятельный. Его файлы, инфраструктура и отчёт
создаются отдельно от других учебных проектов.

Все команды `scripts/lab.sh` выполняет типизированный Python CLI.
Обработчики сгруппированы по области в стиле `user_service`; оболочка
передаёт аргументы, а адаптеры управляют Ollama, Lima и Hermes.
Оформление Python, shell и команд разработки следует `fastapi-clean-example`.
Для проверки кода: `uv sync --locked`, затем `make check-ci`.

Telegram-код организован по выбранному референсу `crudik`: `entities`,
`application`, `adapters`, `presentation`, `main`; зависимости собирает Dishka.
Правило доступа проверяется до обращения к Hermes. Встроенный Telegram-адаптер
Hermes отключён, чтобы сообщения получал один процесс.

## Структура

```text
agent-research-lab/
├── README.md
├── .editorconfig
├── .gitignore
├── .pre-commit-config.yaml
├── .github/        # CI для Python 3.13 на macOS

├── docs/           # статус, управление стендом, журнал ошибок
├── sources/        # неизменённые тексты задания, происхождение материалов
├── infra/          # VM, Docker/Hermes, Ollama, хранение журналов
├── scripts/        # lab.sh, проверки в makefile/, просмотр журналов в evidence/
├── src/agent_lab/  # CLI, прикладные сценарии и инфраструктурные адаптеры
├── src/agent_bot/  # собственный Telegram-код перед Hermes
├── tests/          # pytest: unit, integration, tooling, fixtures, mocks
├── licenses/       # MIT-уведомление заимствованного Self-checker
├── templates/      # память, пример .env, диагностический skill
└── evidence/       # проверенные результаты технической подготовки
```

Секреты, история разговоров, модели и диски VM хранятся вне этой папки.

## Локальный диалог без Telegram

Из корня проекта:

```sh
./scripts/lab.sh chat --cli
```

Выход — `/exit`. Если VM и Ollama остановлены, сначала выполнить
`./scripts/lab.sh start`. CLI использует прежнюю память и инструменты в VM.
Локальный диалог проверен; ошибочный ответ модели о Docker/GPU сохранён
в [журнале ошибок](docs/preparation-errors.md).

Повторный `start` сохраняет работающие VM, Ollama и туннель. При ошибке
запуска освобождаются только компоненты текущей попытки; диски и модели
сохраняются. Поведение проверено на локальном стенде, результаты находятся
в [материалах проверки запуска](evidence/preparation/startup-lifecycle.json).
