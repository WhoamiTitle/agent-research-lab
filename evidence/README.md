# Подтверждающие материалы

В `preparation/` сохранены фактические результаты технической подготовки:
настройка VM, Docker, локальная модель, Hermes и инструменты.
Эти материалы не являются результатами исследования T1–T5 или экспериментов
P1–P5. Для них ещё не задан протокол и не выполнены требуемые серии прогонов.

В репозиторий включены проверки переноса сценариев, адаптации стиля и
жизненного цикла запуска: `refactor-step-01.json`, `style-user-service.json`,
`startup-lifecycle.json`. Подробные прежние журналы Docker, Hermes и модели
остаются локально и не входят в этот набор.

`python-scenarios.json` фиксирует перенос оставшихся команд из оболочки,
проверки аргументов и терминала, повторный `sync` на настоящей VM и
вызов `chat --help`. Содержимое приватной памяти и настроек не экспортируется.

Основные локальные подтверждения:

- `ollama-runtime.txt`, `model-metadata.json`: GPU, выделенный контекст и модель.
- `hermes-memory-check.txt`, `hermes-skill-check.jsonl`: память и выполнение навыка.
- `hermes-web-check.jsonl`: успешный поиск и ошибка чтения в том же прогоне.
- `hermes-browser-check.jsonl`: успешный вызов браузера после исправления настройки.
- `cron-create.txt`, `cron-history.txt`, `cron-output.md`, `cron-runtime.log`:
  назначенное время, фактическое выполнение и ответ контрольной задачи.
- `cron-after-cleanup.txt`: после проверки расписание удалено.
- `local-cli-check.jsonl`: локальный диалог через `scripts/lab.sh chat`
  без Telegram; терминал вызван, но итоговые утверждения модели о Docker/GPU
  неверны. Это проверка доступности CLI, не подтверждение корректности ответа.

Файлы `*.jsonl` содержат вывод Hermes `--format stream-json`. Эта версия CLI
также добавляет текстовый footer `session_id`; при машинном разборе учитывать
только строки с JSON-объектами. При запуске через Compose также присутствуют
сообщения init контейнера. Исходный вывод сохранён.

Перед добавлением материалов:

1. Указать, какая проверка выполнена и при каких условиях.
2. Сохранить действительный результат, включая ошибки и ограничения.
3. Проверить содержимое на токены, ключи, персональные и закрытые данные.
4. Подготовить пригодную для публикации копию, обозначив удалённые сведения.

Необработанные приватные материалы можно хранить в `evidence/private/`:
каталог исключён через `.gitignore`. Это исключение само по себе не
обезличивает файлы и не защищает содержимое других каталогов.

Не создавать пустые результаты прогонов, таблицы с вымышленными значениями
или журналы, представляющие запланированные проверки как выполненные.
